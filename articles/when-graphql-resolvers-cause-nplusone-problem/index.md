I learned which situation causes the N+1 problem while implementing a GraphQL server with [gqlgen](https://gqlgen.com/). Here are the key points.

## Splitting resolvers

To avoid over-fetching from the DB, we can set `resolver: true` on a model's field in `gqlgen.yml`. This configuration tells gqlgen to generate a separate resolver in `schema.resolvers.go`, so that the field is resolved only when it's requested.

```yaml
# in gqlgen.yml
models:
  Repository:
    fields:
      owner:
        resolver: true
      issues:
        resolver: true
  Issue:
    fields:
      author:
        resolver: true
```

```go
// In schema.resolvers.go
func (r *queryResolver) Repository(ctx context.Context, name string, owner string) (*model.Repository, error) {
	return r.Services.GetRepositoryByParams(ctx, name, owner)
}

func (r *repositoryResolver) Issues(ctx context.Context, obj *model.Repository, after *string, before *string, first *int32, last *int32) (*model.IssueConnection, error) {
	// ...
}

func (r *issueResolver) Author(ctx context.Context, obj *model.Issue) (*model.User, error) {
	return r.Services.GetUserByID(ctx, obj.Author.ID)
}
```

After running the command, gqlgen generates code in `generated.go` that calls the `Author()` method for each issue.

## N+1 problem

Since `GetUserByID()` method is called for each issue and runs a SQL query every time, a single GraphQL query for a repository results in causing N+1 queries.

```go
// In services/users.go
func (u *userService) GetUserByID(ctx context.Context, id string) (*model.User, error) {
	dbUser, err := u.q.GetUserByID(ctx, id)
	if err != nil {
		return nil, err
	}
	user := convertUser(dbUser)
	return &user, nil
}
```

```go
// In graph/db/users.sql.go, generated by sqlc
const getUserByID = `-- name: GetUserByID :one
SELECT id, name, project_v2 FROM users WHERE id = ?
`

func (q *Queries) GetUserByID(ctx context.Context, id string) (User, error) {
	row := q.db.QueryRowContext(ctx, getUserByID, id)
	var i User
	err := row.Scan(&i.ID, &i.Name, &i.ProjectV2)
	return i, err
}
```
